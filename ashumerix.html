Ashumerix

Building a responsive and scalable company website

Introduction

Ashumerix is a company website project focused on translating business identity into a clean, functional, and scalable digital presence.

Unlike concept-driven projects, this was rooted in working within constraints — including fixed content, defined branding direction, and the need for a responsive, production-ready interface.

The goal was not just to design something visually appealing, but to create a system that could hold up in real-world use and future updates.

The Problem

Many company websites suffer from:

  • poor content hierarchy
  • inconsistent layouts
  • lack of responsiveness across devices
  • fragile design systems that break when content changes

In this case, an additional constraint was critical:

The content itself could not be altered.

This introduced a real-world challenge:

how do you improve clarity and usability without changing what is being said?

Design Objective

To design and build a company website that:

  • presents information clearly without modifying content
  • maintains visual consistency across sections
  • remains stable regardless of image or content changes
  • is fully responsive across all screen sizes
  • balances aesthetics with real implementation constraints

Understanding the Context

This project required thinking beyond the user alone and considering:

  • business identity and tone
  • content rigidity
  • developer constraints
  • scalability of layout

Key considerations:

  • content-heavy sections needed structure, not reduction
  • images needed to be flexible without breaking layout
  • responsiveness had to be handled manually through CSS

My Role

UI Design Front-End Development Layout Structuring Component Design

Process

1. Content Analysis

Before designing, I studied the content in its existing form.

This allowed me to:

  • understand hierarchy without rewriting it
  • identify sections that needed restructuring
  • determine how to visually guide the user

2. Layout Structuring

I focused on building a layout system that:

  • groups related information clearly
  • creates visual rhythm across sections
  • improves readability without reducing content

This was less about adding elements, and more about organizing what already exists.

3. Responsive Design Strategy

Responsiveness was handled through:

  • custom CSS media queries
  • flexible grids
  • adaptive spacing

The goal was to ensure:

  • consistency across screen sizes
  • no layout breakage
  • smooth scaling of components

4. Image Handling

A key challenge was ensuring that replacing images in the future would not break the design.

To solve this, I:

  • used fixed containers with controlled proportions
  • ensured images scale without distortion
  • maintained consistent placement regardless of content changes

5. UI Refinement

Visual decisions focused on:

  • a minimal, professional color palette (black, grey, white, orange)
  • consistent spacing and alignment
  • subtle interactions for engagement

The aim was clarity over decoration.

Key Design Decisions

Content-first design

Instead of redesigning content, I structured it to improve clarity.

Constraint-driven design

Worked within fixed text and branding instead of altering them.

Stability over flexibility

Ensured the layout remains intact even when content changes.

Manual responsiveness

Handled responsiveness intentionally rather than relying on frameworks.

Trade-offs & Considerations

  • limited ability to simplify due to fixed content
  • balancing visual appeal with strict structure
  • ensuring responsiveness without overcomplicating CSS

Outcome

The result is a fully responsive, structured company website that:

  • improves readability and clarity
  • maintains consistency across devices
  • remains stable under content changes
  • reflects a clean and professional brand presence

Reflection

This project strengthened my ability to:

  • design within real-world constraints
  • think like both a designer and a developer
  • prioritize structure and scalability over visual excess

It reinforced an important principle:

good design is not just how something looks, but how well it holds up over time
